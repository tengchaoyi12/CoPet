# 静态宠物与 Codex 前台清除提醒设计

## 背景

CoPet 当前会根据待机、交互、拖动和 Agent 状态切换精灵动画。Codex 任务完成后，宠物上方会持续显示未读完成提醒，直到用户点击提醒或主动关闭。

本次调整希望让宠物保持稳定的桌面挂件形态，同时把宠物本身变成 Codex 的快捷入口。用户通过任意方式回到 Codex 后，已完成任务的提醒应自动消失，避免用户已经查看结果后仍被重复提示。

## 目标

- 宠物始终显示默认静态帧，不播放任何精灵、交互、状态或情绪动画。
- 保留拖拽宠物窗口调整位置的能力。
- 短按宠物打开 Codex；拖拽结束不触发打开动作。
- Codex 成为前台应用时，自动清除全部已完成提醒。
- 等待处理和失败提醒不因 Codex 获得焦点而被清除。

## 非目标

- 不改变任务事件采集、去重和持久化格式。
- 不增加按任务精确识别 Codex 当前页面的能力。
- 不修改提醒气泡的视觉样式。
- 不删除现有动画和交互基础设施，只在宠物窗口中停用其视觉输出。

## 方案选择

### 采用方案：macOS 原生前台应用监听

在 Rust 后端通过 `NSWorkspace` 的应用激活通知监听前台应用变化。当 Codex 对应的应用成为前台时，由任务通知存储清除所有 `completed` 状态提醒，再通过现有 Tauri 事件向宠物窗口发送最新状态。

该方案是事件驱动的，不需要前端轮询，且能够覆盖用户点击 Dock、使用快捷键切换应用、点击系统通知或从其他入口回到 Codex 的情况。

### 未采用方案

- 前端轮询当前前台应用：实现简单，但会持续耗用资源，且需要额外处理窗口隐藏和 WebView 暂停。
- 仅在点击宠物或提醒时清除：无法覆盖用户通过其他方式回到 Codex，不符合需求。

## 静态宠物行为

宠物窗口固定选择默认 `idle` 行的第一帧，并关闭精灵动画。Agent 状态、点击、悬停、拖动落地和完成注意信号不再改变宠物显示帧，也不显示情绪覆盖层。

任务提醒仍按现有规则显示在宠物上方。完成事件仍创建提醒，但不再驱动庆祝动画；声音是否播放不作为本次调整的一部分，默认随静态模式一并关闭交互和 Agent 状态音效，避免形成“宠物不动但仍发出动作音效”的不一致体验。

## 点击与拖拽

宠物继续支持主按钮拖拽。交互层记录按下位置和实际移动距离：

- 指针释放前未超过拖拽阈值，视为短按，调用新的 Tauri 命令打开 Codex 主界面。
- 超过阈值后视为拖拽，只移动窗口，不触发打开动作。
- 双击和快速连续点击复用同一个打开动作，并在一次指针序列中去重。
- 右键和长按继续保留现有菜单行为。

打开 Codex 使用现有 `task_opener` 的应用回退能力，不要求存在具体任务标识。

## Codex 前台检测与提醒清理

macOS 监听 `NSWorkspaceDidActivateApplicationNotification`，并根据应用标识识别 Codex。当前桌面客户端可能从 `ChatGPT.app` 启动，但使用 Codex 的应用标识，因此实现应以经过验证的 bundle identifier 为主，并保留可测试的纯函数判断。

检测到 Codex 成为前台后：

1. 获取任务通知存储的独占访问。
2. 删除全部 `completed` 状态提醒。
3. 保留 `waiting`、`failed` 和运行中状态。
4. 持久化新状态。
5. 通过现有 `pet-state-changed` 事件通知所有窗口刷新。

如果前台应用信息不可用或标识不匹配，不执行清理。该路径不得让 CoPet 崩溃，也不得影响 Codex。

## 数据流

```text
用户短按宠物
  -> 前端区分短按与拖拽
  -> Tauri 命令
  -> 打开 Codex 主界面

Codex 成为前台
  -> NSWorkspace 激活通知
  -> Rust 判断应用标识
  -> 清除全部 completed 提醒
  -> 持久化通知状态
  -> pet-state-changed
  -> React 隐藏完成气泡
```

## 错误处理

- 打开 Codex 失败时使用现有错误提示机制，不改变提醒状态。
- 前台监听安装失败时记录本地错误，保留提醒，不做误清除。
- 持久化失败时保留内存状态并记录错误；后续事件可再次尝试保存。
- 非 macOS 平台保留可编译的空实现，不声称支持前台自动清理。

## 测试策略

前端 Playwright 测试覆盖：

- 宠物使用静态帧且 `data-animated="false"`。
- Agent、完成和交互事件不会改变宠物显示状态。
- 短按调用打开 Codex 命令。
- 超过阈值的拖拽不调用打开命令。
- 双击不会重复调用打开命令。

Rust 集成测试覆盖：

- Codex 应用标识判断。
- 清除全部完成提醒。
- 等待和失败提醒继续保留。
- 没有完成提醒时操作幂等。
- 前台激活后生成的运行时更新和持久化状态一致。

最终进行一次 macOS 现场验收：拖动宠物不会打开 Codex，短按宠物能够打开 Codex；创建完成提醒后，通过其他方式切回 Codex，提醒自动消失。

## 验收标准

- 宠物在待机、任务运行、任务完成、悬停、点击和拖拽过程中始终显示同一静态帧。
- 宠物可拖动到新位置，释放时不会误打开 Codex。
- 短按宠物只打开一次 Codex。
- Codex 成为前台后，所有完成提醒消失。
- 等待和失败提醒不会被前台切换误删。
- 现有前端测试、Rust 测试、构建和格式检查通过。
