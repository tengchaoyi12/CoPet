# Codex 快捷操作紧凑卡片设计

## 背景

现有快捷操作提醒已经具备安全的一次性继续和权限批准能力，但界面在宠物窗口的窄宽度下同时展示状态、标题、摘要、待执行说明、工具、命令、工作目录、授权范围和两个操作按钮。真实渲染中，三张卡片会形成难以快速扫描的信息墙。

本轮只调整前端信息架构，不改变 Rust 动作协议、动作有效期、一次性决定或提醒清理规则。

## 设计目标

- 用户无需切回 Codex，就能一眼判断发生了什么以及最安全的下一步。
- 默认卡片只展示任务名、一项关键摘要和一个主操作。
- 同时最多展示三张卡片，避免遮挡宠物和占满屏幕。
- 详细上下文按需在当前卡片内展开，同时只展开一张。
- 需要用户回复、输入或选择的任务不出现继续或批准按钮。

## 信息层级

### 权限请求

折叠态必须展示：

1. `等待执行权限`
2. 任务标题
3. 待批准命令；缺少命令时回退到动作说明
4. 主按钮 `仅允许这次`
5. `详情`入口

展开态补充：

- 动作用途
- 工具名
- 完整的脱敏命令
- 工作目录
- `仅允许本次操作`范围说明
- 低权重操作 `在 Codex 中处理`

权限对象不能只藏在详情中，否则用户会在不知道批准内容的情况下点击主按钮。

### 普通继续

折叠态展示 `等待继续`、任务标题、Codex 声明的下一步和 `继续执行`。详情内展示更完整的下一步说明以及 `在 Codex 中处理`。

### 需要用户回复

当提醒为 waiting，但不存在可执行的安全快捷动作时，状态显示 `需要你的回复`，唯一按钮为 `打开 Codex`。CoPet 不代替用户回答，也不显示继续或批准按钮。

### 其他提醒

completed、failed 和 running 继续保留现有打开任务行为，不引入新的动作语义。

## 多任务与展开行为

- 按现有提醒顺序只渲染前三张，不修改 store，不关闭未显示提醒。
- 点击某张卡片的 `详情`只展开该卡片，并收起先前展开的卡片。
- 再次点击同一 `详情`则收起。
- 每个动作按钮继续按自己的 `actionId`解析，展开状态不参与动作协议。
- 提醒被移除后，对应展开状态自然失效。

## 安全边界

- `仅允许这次`只调用 `allowOnce`。
- `继续执行`只调用 `continueOnce`。
- `打开 Codex`及`在 Codex 中处理`继续先 fallback，再打开原任务。
- `详情`、关闭按钮、卡片展开和显示上限都不会批准动作。
- 过期、不可快速处理、需要选择或输入的动作不显示快捷批准。
- completed 前台清除、waiting/failed 保留的现有逻辑不变。

## 可访问性

- `详情`使用真实按钮和 `aria-expanded`、`aria-controls`。
- 主操作使用可见文案，不仅依赖颜色表达含义。
- 命令在折叠态保留可读文本，长内容视觉截断但保留完整 title。
- 处理期间只禁用当前动作相关按钮，其他卡片保持可操作。

## 设计审查结论

`design-consultation` 确认核心体验为“一眼看懂并安全处理”；`design-review` 的真实渲染证明现有卡片层级过载；`plan-design-review` 确认本方案覆盖权限透明度、渐进披露、多任务上限、可访问性和动作安全边界，可以进入实现。

## 验收标准

- 初始视图最多三张卡片，不再直接铺开工具、目录和范围信息。
- 权限卡折叠时仍显示待批准命令。
- 同一时间最多展开一张详情。
- 权限主按钮为 `仅允许这次`，普通继续为 `继续执行`。
- 需要用户回复的 waiting 提醒只显示 `打开 Codex`。
- 现有 actionId 隔离、fallback、过期和错误反馈测试无回归。
