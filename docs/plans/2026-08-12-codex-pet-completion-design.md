# Codex 任务完成提醒宠物设计

## 背景

CoPet 已具备 Tauri 桌面窗口、React 宠物界面、Rust 本地运行时、CLI 适配器和 Codex Hook 安装能力。当前 Codex 的 `Stop` 事件只会让全局宠物显示通用的 `Done.` 消息，缺少面向具体任务的持久提醒、去重和跳转能力，也没有开机自启动设置。

本次改造以现有 CoPet 为基础，先聚焦 Codex：当某个 Codex 任务结束时，桌面宠物主动庆祝并发出消息，提醒用户回到对应任务查看结果。

## 目标

- Codex 任务运行、等待、完成和失败时，宠物表现出对应状态。
- 任务完成后显示中文提醒：`任务完成啦，快去看看吧。`
- 多任务并行时保留各任务的独立提醒，并按照优先级展示。
- 用户点击提醒时优先打开对应 Codex 任务；无法精确跳转时打开 Codex 主界面。
- 同一轮任务只提醒一次，应用重启后仍保留尚未处理的提醒，但不重复播放完成通知。
- Hook 和宠物应用出现异常时不能阻塞 Codex 本身。
- 提供 macOS 登录后自动启动开关。
- 所有状态和提醒仅保存在本机，不增加云端服务和遥测。

## 非目标

- 本阶段不重写 CoPet 的整体框架。
- 本阶段不扩展 Claude Code、Gemini CLI 等其他适配器的任务级通知。
- 本阶段不承诺所有 Codex 版本都支持精确深链；必须提供稳定的主界面回退。
- 本阶段不实现跨设备同步、账户系统或云端消息推送。

## 现有基础与差距

现有链路如下：

```text
Codex Hook
  -> localhost 事件端点
  -> Rust RuntimeCore
  -> 状态引擎与消息列表
  -> Tauri 事件
  -> React 宠物窗口
```

可以直接复用的能力：

- `codex.rs` 已能安全合并 `~/.codex/hooks.json` 和 `config.toml`。
- 本地 HTTP 服务已有随机令牌认证。
- `RuntimeEvent`、`EventStateEngine`、`RuntimeUpdate` 已形成事件到界面的主干。
- 宠物窗口已有动画、消息气泡、关闭和点击交互基础。

需要补齐的能力：

- 当前消息按 `agent` 覆盖，不能区分同一 Codex 中的多个任务。
- 当前事件缺少稳定的轮次去重键、任务标题和跳转目标。
- `session.stop` 仅生成通用 `Done.`，提醒不会持久保存。
- 当前状态是单一全局状态，尚未按任务优先级聚合。
- 当前项目没有登录自启动集成。

## 总体架构

保留现有 Tauri + React + Rust 架构，只在主链路中增加任务语义：

```text
Codex Hooks
  -> Hook 助手（尽量提取任务、轮次和结果信息）
  -> 本地令牌认证端点
  -> Codex 事件标准化
  -> 任务状态仓库
  -> 状态优先级聚合
  -> Tauri RuntimeUpdate
  -> 宠物动画 + 任务提醒气泡
  -> 点击提醒后精确跳转或回退打开 Codex
```

Rust 负责可信事件接收、状态机、去重、持久化和打开目标；React 只负责展示和用户交互。所有 Tauri 命令继续通过 Hook 封装，组件不直接调用 `invoke`。

## 事件模型

在兼容现有字段的前提下，为 `RuntimeEvent` 增加可选任务语义：

- `session_id`：Codex 会话标识。
- `turn_id`：本轮任务标识；缺失时由适配器使用可复现字段生成回退键。
- `task_title`：任务标题或安全截断后的用户提示摘要。
- `action_target`：可选的任务深链或可恢复目标。
- `outcome`：成功、失败或中断。
- `summary`：可显示的完成或错误摘要。

归一化层只接受允许的事件类型，并将 Codex Hook 映射为：

| Codex 事件 | 任务状态 | 宠物表现 |
|---|---|---|
| 用户提交、思考、工具调用 | `running` | 工作动画 |
| 权限或输入请求 | `waiting` | 醒目等待动画与气泡 |
| 正常停止 | `completed` | 庆祝动画与完成提醒 |
| 错误或中断 | `failed` | 失败动画与摘要 |
| 无活动任务 | `idle` | 待机动画 |

事件字段缺失时采用保守降级：允许显示通用提醒，但不伪造不可验证的精确任务链接。

## 任务状态与优先级

新增任务级记录，至少包含：

- 唯一标识：`agent + session_id + turn_id`。
- 当前状态和最近更新时间。
- 标题、摘要和跳转目标。
- 是否已提醒、是否已读、是否已关闭。

同一轮任务的重复完成事件只更新已有记录，不再次播放庆祝和声音。任务状态优先级为：

```text
waiting > failed > completed > running > idle
```

宠物主动画由最高优先级未处理任务决定；气泡列表保留多个任务，让用户逐条查看。完成提醒持续存在，直到用户点击、关闭或明确标记已读。

## 完成提醒体验

正常完成时：

1. 宠物切换到一次庆祝动画。
2. 播放一次已有提示音或专用完成音。
3. 显示 `任务完成啦，快去看看吧。`。
4. 有任务标题时，在消息中补充安全截断后的标题。
5. 用户点击消息后执行打开动作，并将该提醒标记为已读。

失败或中断时不显示“任务完成”，而是显示失败状态和可用的错误摘要。

## 跳转策略

点击任务提醒时按以下顺序处理：

1. 使用事件中经过校验的 Codex 任务深链或应用内部目标。
2. 如果当前 Codex 版本不提供可用深链，则激活 Codex 桌面应用或打开 Codex 主界面。
3. 若仍失败，保留提醒和任务标题，并向用户显示可恢复的错误提示，不静默丢失消息。

深链格式不在设计阶段硬编码；实施时通过本机 Codex 能力和官方资料验证，并为回退路径编写测试。

## 持久化与恢复

任务提醒使用本地、有限容量的 JSON 状态文件保存，位置遵循 CoPet 应用数据目录，不写入项目目录或云端。持久化采用临时文件加原子替换，避免应用异常退出造成文件损坏。

启动恢复规则：

- 恢复未读的等待、失败和完成提醒。
- 恢复提醒后不重复播放完成音和庆祝动画。
- 已关闭或超过保留期限的记录定期清理。
- 状态文件不可读时记录本地错误并从空状态安全启动。

## Hook 安装与安全

- 延续现有“合并而非覆盖”的 Hook 安装方式。
- 修改用户配置前生成可恢复备份，并保留卸载路径。
- Hook 请求仅发送到回环地址，并携带随机令牌。
- 服务端拒绝无效令牌、未知事件和不符合约束的字段。
- Hook 脚本必须快速失败并返回，不因 CoPet 未启动、端口不可用或载荷异常而阻塞 Codex。
- 日志和持久化内容不保存完整敏感提示，只保存显示所需的截断标题和状态元数据。

## macOS 登录自启动

设置页增加“登录后自动启动”开关。优先采用 Tauri 官方维护的自启动能力；开关状态必须与系统实际注册状态一致，而不是只保存一个界面布尔值。

首次安装默认关闭，用户主动开启后注册登录项；关闭后立即注销。开机重启后由 macOS 启动 CoPet，应用恢复未读提醒并重新监听 Codex 事件。

## Codex 优先范围

代码层保留 CoPet 的多适配器结构，但本阶段界面只暴露 Codex 的任务完成提醒能力。其他适配器不删除，避免破坏未来扩展；它们不会自动获得未经测试的任务级状态逻辑。

## 测试策略

Rust 集成测试覆盖：

- Codex 事件到任务状态的转换。
- 状态优先级和多任务聚合。
- 完成事件去重。
- Hook 配置合并、备份和卸载恢复。
- 持久化写入、重启恢复和损坏文件降级。
- 深链打开失败后的主界面回退。
- 无效令牌、未知事件和缺失字段的处理。

React 的 Playwright 测试覆盖：

- 完成、等待、失败消息的展示差异。
- 多任务提醒列表和关闭行为。
- 点击提醒调用打开任务 Hook，并更新已读状态。
- 自启动设置显示系统真实状态并能切换。

最终进行一次真实 Codex 端到端验收：运行任务、触发完成、确认宠物只提醒一次、点击能够返回 Codex，并验证应用重启后的未读恢复。

## 验收标准

- 一个 Codex 任务正常结束后，宠物在短时间内显示中文完成提醒。
- 重复收到同一轮完成事件时不会重复通知。
- 两个并行任务能够生成两条可区分、可分别处理的提醒。
- 权限等待优先于完成消息影响宠物主状态。
- 点击提醒能够打开对应任务，或明确回退到 Codex 主界面。
- CoPet 未运行或异常退出不会影响 Codex 任务完成。
- 登录自启动可以在设置中开启和关闭，重启登录后行为符合设置。
- 数据仅保存在本机，完整测试和构建检查通过。
